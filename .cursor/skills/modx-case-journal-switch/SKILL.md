# Кейс + журнал: `[[$switch]]`

Если в **кейсе** и в **журнале** есть описания **одного продукта** — в **аннотацию** (поле `introtext`) подгружается (с новой строки) `[[$switch]]` с настройками TV **Site → URL-href**.

## Аннотация (`introtext`)

После блока `<h1>` / `<h3>` — с новой строки:

```
[[$switch]]
```

В PHP-строках (deploy-скрипты): `"...\n[[\\$switch]]"`.

Пример:

```html
<h1>ЖКХ Ответы</h1>
<h3>Платформа для УК: обращения<br> из ГИС ЖКХ без просрочек</h3>
[[$switch]]
```

Чанк `switch` рисует кнопки «Кейс» / «Журнал»; на текущем разделе кнопка `disabled` (`parent` 2 = портфолио, 18 = журнал).

## TV `URL-href` (категория Site)

На **обоих** ресурсах задать TV `URL-href` (без ведущего `/`):

| Ресурс | `URL-href` |
|--------|------------|
| кейс | URI статьи журнала, напр. `journal/gis-zhkh-bez-prosrochek` |
| статья | URI кейса, напр. `portfolio/jkh-otvety` |

## Чеклист при новой паре продукт ↔ статья

- [ ] у кейса в `introtext` есть `\n[[$switch]]`
- [ ] у статьи в `introtext` есть `\n[[$switch]]`
- [ ] TV `URL-href` на кейсе → URI журнала
- [ ] TV `URL-href` на статье → URI кейса
- [ ] в deploy-скриптах intro не затирает `[[$switch]]`

## Не ставить

- если нет парной страницы (только кейс или только статья) — `[[$switch]]` и `URL-href` не нужны.

## Кэш после деплоя от root

Скрипты деплоя под `root` не должны оставлять `core/cache` от root: иначе `www-data` не пишет кэш сниппетов (`sortText`, `request`) — пустые аннотации в плитках и пустой AJAX `action=next`.

После правок кэша:

```bash
chown -R www-data:www-data /var/www/studiowest.ru/core/cache
```

Листинг плиток берёт текст из `introtext` через `[[!sortText? &id=`[[+id]]`]]` (чанк `WfOpsWrapper`) — не передавать сырой `introtext` в `&par=`, иначе `]]` из `[[$switch]]` ломает тег.
